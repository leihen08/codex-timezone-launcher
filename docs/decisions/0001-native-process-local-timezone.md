# ADR-001：使用 Win32 原生 UI 和子进程级 TZ

## 状态

已接受

## 日期

2026-09-07

## 背景

启动器需要用 Rust 提供清爽的 Windows 桌面界面，为 Codex/ChatGPT 客户端选择时区，同时不能更改系统时区或强制结束现有客户端。它还需要自动发现 Store/传统安装，并在不保存 IP 的前提下通过固定 HTTPS 服务定位 IANA 时区。

## 决策

使用 Win32 原生控件和系统 GDI 绘制界面，使用 Windows Toolhelp/注册表 API 发现与检测进程，使用 `std::process::Command` 创建带独立 `TZ` 环境的子进程。公网定位使用 Windows WinHTTP，只请求固定的 `https://ipapi.co/json/`，禁用重定向并设置超时和响应大小上限。

`TZ` 只应用于启动器创建的客户端进程及其后代；不调用 Windows 系统时区修改 API。若目标客户端已经运行，工作流只保存设置并返回警告，不包含终止进程的能力。

## 考虑过的替代方案

### Tauri/WebView

- 优点：HTML/CSS 布局灵活。
- 缺点：引入 WebView 前后端边界、更多打包组件和更大的攻击面。
- 结论：这个单窗口工具不需要 Web 技术栈。

### eframe/egui

- 优点：纯 Rust、开发速度快。
- 缺点：自绘控件不完全遵循 Windows 原生交互和无障碍行为，二进制及依赖更多。
- 结论：Win32 控件更符合“原生桌面界面”和小体积目标。

### 修改 Windows 系统时区

- 优点：所有应用可见。
- 缺点：影响整个系统、通常需要额外权限，并违背进程隔离要求。
- 结论：拒绝；仅设置子进程环境。

### Shell 命令或快捷方式包装

- 优点：实现简单。
- 缺点：容易产生 quoting/injection 问题，路径和环境继承不够明确。
- 结论：拒绝；使用参数化进程 API。

## 后果

- Release 程序不需要 WebView 或额外运行时。
- Win32 代码需要明确管理句柄、字体、画刷和 UI 线程消息。
- Electron/JavaScript 运行时通常遵循 `TZ`；直接调用 Windows 原生时区 API 的极少数功能仍可能遵循系统时区。
- 固定定位端点降低 SSRF 面并使隐私行为可审计，但服务离线时只能清晰降级为手动选择。
